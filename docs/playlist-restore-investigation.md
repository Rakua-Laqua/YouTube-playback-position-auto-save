# プレイリスト再生後の再起動で先頭の動画に戻る件の調査

記録開始: 2026-09-24

## 症状

プレイリストを長時間再生した後にChromeを閉じて開き直すと、#6まで進んでいたのに#1の動画で復元されることがある。短時間の再生後に閉じた場合は、閉じる前の動画で正しく復元される。これとは別に、画面上では3番目に表示されている動画のURLが `index=4` になっている、というずれも観察されている。

## これまでに確認したこと

この拡張機能はURLを読むだけで書き換えない。`location.search` を読んでいるのは、動画IDの取得と `?t=` の有無の判定の2か所だけである。`history.pushState` / `replaceState`、`location` への代入、ページの再読み込みはどのファイルにもない。影響できるのは同じ動画の中での再生位置（`currentTime`）と一時的な消音に限られるため、どの動画を開くかは変えられない。

併用しているYouTube NonStop（v0.9.2、ID `nlkaejimjacpillmajjnopmpbkbnocid`）も、インストール済みのソースを読んだ範囲ではURLや履歴に触れていない。していることは、「続きを視聴しますか？」の確認画面を閉じること、操作していない間は `video.pause()` を実行しないこと、メディアキーの一時停止の処理を横取りすることの3つだけである。本拡張との関わりは、保存位置へ移動する前の一時停止（`pauseForRestore`）がNonStopに止められ、移動の直前に音が一瞬出ることがある点だけで、どの動画が開くかには影響しない。

YouTubeが開く動画を決めるのは `v=` であり、`index=` は補助的な情報である。そのため `index` がずれていても、別の動画が開くことはない。ずれの原因としては、プレイリスト内の削除済み・非公開の動画を、画面の番号は飛ばして数え、`index` は飛ばさずに数えていることが考えられる（確度は中程度）。

以上から、原因の候補はChromeのセッション復元とYouTube本体の2つに絞られる。短時間の再生では正しく復元されることから、長時間再生した後にだけ成り立つ条件が関係していると考えられる。例えば、PCのスリープ・シャットダウン・更新による再起動でChromeが強制終了されること、タブのクラッシュ、タブの破棄などである。いずれも現時点では確かめられていない。

## 診断ログ

`background.js` が、Chromeから見たYouTubeタブのURLを `chrome.storage.local` の `diag_nav_log` に記録する。Chromeのセッション復元が使うのはタブのURLなので、ページの中ではなくtabs APIから見た値を記録している。記録は最大500件で、古いものから消える。書き出しと削除は、ポップアップの設定画面にある「診断ログ（一時的）」から行う。

| event | 記録するタイミング | 主な項目 |
| --- | --- | --- |
| `browser-startup` | Chrome起動時 | その時点のYouTubeタブ一覧（`url` または `pendingUrl`、`status`、`discarded`） |
| `extension-install` / `extension-update` | 拡張機能のインストール・更新・再読み込み | 同上 |
| `tab-created` | YouTubeのタブが開いたとき | タブのURL |
| `tab-updated` | URLの変化（プレイリストの次の動画への移動を含む）、読み込みの開始、タブの破棄 | `urlChanged`、`status`、`discarded`、`parsed.v` / `list` / `index` |

タブを閉じたとき（`tabs.onRemoved`）は記録しない。Chromeが終了するときはService Workerの書き込みが完了する保証がないため、記録があるかどうかから終了の仕方を判断できないからである。

## ログの読み方

症状が出たら、再起動の直後にログを書き出し、最後の `browser-startup` とその直前の記録を比べる。

- 起動直前の最後の `tab-updated` が#6なのに、`browser-startup` のタブが#1を指している場合は、Chromeが古いURLを復元している。閉じ方（強制終了されたかどうか）を確かめる。
- 起動直前の最後の `tab-updated` がすでに#1を指している場合は、閉じる前の時点でYouTube側が#1に移動していた。その直前の記録から、いつ移動したかを追う。
- `browser-startup` のタブが#6で、その後の `tab-updated` で#1に変わっている場合は、YouTubeが読み込み後に移動させている。

ログでは分からないことが2つあるため、症状が出たときに手元で控えておく。1つはChromeの閉じ方（×ボタンか、PCのシャットダウンやスリープか）、もう1つは起動時に「ページを復元しますか？」が表示されたかどうかである。

## 片付け

原因が分かったら、診断ログの機能（`background.js` の診断ログの部分、ポップアップの「診断ログ（一時的）」、`shared.js` の `DIAG_LOG_KEY` / `appendDiagEntry` / `parseWatchUrl`、関連するテストと翻訳文字列）を取り除き、このメモに結論を書き足す。
